# Бэклог до пред-релиза — итог (zcode + аудит наёмного ревьюера, 24.10.2026)

Концепция владельца (правила): максимально нативная сборка **без внешних зависимостей** (исключение по решению владельца: tree-sitter в редакторе, ADR-0002); **две темы** (+системная); **сайдбары однотипны** (визуально: токены, шрифты, паттерн строк; механика у каждого приложения своя — замечание о механике плеера живёт отдельной карточкой); **шапка подстраивается под тему** (системный тулбар); **контент и заголовки идентичны** (типографика — по карте соответствий, с приёмочной точкой до массовой замены). Первая цель — **рабочий нативный плеер**.

Каждая волна заканчивается приёмочной точкой (владелец смотрит результат).

## Порядок исполнения

**G2 → P1 → P5 → P2+P3 → P4 → P6 → P7 → B-волны → E-волны.**

## ПЛЕЕР (приоритет 1)

- **G2 (предусловие).** `Look.key` → публичный; слияние `Theme` плеера в `Look` пакета (G2 формально общий, исполняется в плеере).
- **P1. Одна ось темы.** Снести `AppearancePreset` (aero/obsidian/system): Светлая = системное стекло, Тёмная = плотный матовый, +Системная — через `Look`. Включает: миграцию сохранённых настроек живой копии (aero→light, obsidian→dark, system→system), сохранение правила «тот же пресет не сбрасывает шаблон окна» при переезде на Look, подменю трея (Tray), переписывание части PresentationTests (7 тестов).
- **P5. Материалы по Apple.** Убрать самодельную оптику: слои lift/sheen/foot, rim-градиент, плотность 0.78 у NSVisualEffectView — системные материалы как есть; тёмная тема — плотный `Palette.ground` (свой градиент Matte — параметр материала, решить при выполнении). Сократить ручной Reduce-Transparency-фолбэк до системного поведения. **Приёмочная точка: окно на обоях владельца.**
- **P2. Шапка.** Системный unified toolbar (уже есть): убрать дублирующее кастомное, сепаратор/фон — системе; `toolbarChrome` 52 → `Metrics.strip` пакета (дубль убрать).
- **P3. Сайдбар — однотипный паттерн.** Шрифты/цвета/hover/выделение — токены; заголовки секций — label-стиль; свои шрифтовые хардкоды сайдбара уезжают в P3 (объединён с типографикой сайдбара). Ширины шаблонов (200/176–240) — оставить плеерными до отдельного решения владельца о единой геометрии (развилка №5).
- **P4. Типографика — все размеры на токены.** Карта: 15→display **только после показа владельцу** (размеры приёмкой не покрывались), 13→body, 12→bodyMuted, 11 mono — mono, капсоны — label.
- **P6. Контролы.** Door — a11y-лейблы (valueOn/valueOff уже в пакете); прогресс — цвета токенами; громкость — системный (уже).
- **P6a. `CFBundleDocumentTypes`** — открытие музыки из Finder/`open` (нативность; да — решение zcode, вето владельца возможно).
- **P7. Пред-релиз.** Предлагаю версию **0.2.0** (владелец вправе переименовать), NOTES/CHANGELOG, `build.sh release`, полный прогон, обновление рабочей копии. Публикация (dmg/appcast/tap, нотаризация) — по слову владельца; до слова — только локальная сборка, ad-hoc (прежнее решение). Двигатель/плейлисты/обложки вне юнит-тестов — принятый риск, записан.
- **Вне пред-релиза (осознанно):** P-07 «пять атмосфер joer», P-08 эквалайзер/визуализаторы; механика открытия сайдбара/ресайза — отдельная карточка-находка.

## БРАУЗЕР (после плеера)

- **B1. Typography-adoption.** Это редизайн размеров, не замена 1:1 (8/9/12.5/14/15/17 без прямых токенов): карта соответствий → приёмочная точка владельцем → поэтапная замена (панели → хром → контент) со скриншот-сверкой каждого этапа.
- **B2. Сайдбар — визуальная унификация** (шрифты/цвета/hover токенами); механика колонки вкладок (row 28, DragStrip) и рейка настроек (row 30) — остаются своими.
- **B3. Материалы:** SiteCard `.menu` — эталон; кастомное стекло не расширять.
- **B5. Пред-релиз:** 1.0.7 «унификация» или 1.1 — развилка владельца; выпуск после P7.
- **B4 (вне очереди).** Стартовый экран — кандидат по слову владельца; виджеты и система тем — вне пред-релиза.

## РЕДАКТОР (по HANDOFF)

- **E1. Настройки:** системное Settings-окно с LookPicker — первый боевой потребитель рецепта (ждать правок рецепта по ходу).
- **E2. Сайдбар:** визуальная унификация (sourceList остаётся системным); дерево файлов как функционал — в волне F-02 по HANDOFF, тут только вид.
- **E4. Функционал:** сессии/недавние — подключение сторов (Recents/SessionState к AppDelegate/меню), восстановление при запуске; синтакс — tree-sitter по ADR-0002, **ждёт команды владельца на merge спайка**.
- **E3. Хром (только вид):** статус-бар по рецептам линейки; панель поиска — системный вид NSTextFinder (функционал поиска — волна 5, вне).
- **E5. Пред-релиз:** шаг сборки .app; имя/bundle id/версия/иконка — решения владельца; создать CHANGELOG/NOTES.
